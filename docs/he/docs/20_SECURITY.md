# 20 — אבטחה (טכני)

**עודכן לאחרונה:** 2026-01-07  
**סוג:** HOW (ארכיטקטורה/אבטחה)

## 1) עקרונות
- **ברירת מחדל חסום**: מי שלא מחובר לא רואה כלום.
- **הרשאות מינימליות**: הלקוח קורא רק מה שחייב.
- **שרת קובע אמת**: פעולות שינוי דרך Cloud Functions.
- **יכולת תחקור**: כל פעולה רגישות (מודרציה/חסימה) נרשמת.

## 2) אימות וזהות
- Firebase Auth: Email/Password+אימות טלפון, Google, Apple.
- אכיפת 18+ לפי תאריך לידה באונבורדינג (ולידציה שרתית).
- שדות נעולים נאכפים בשכבת המוטציות של השרת.

## 3) Firestore Rules — גישת “מחמיר”
- הלקוח לא יכול:
  - לכתוב הודעות
  - לערוך/למחוק
  - לשנות senderUid / timestamps / membership
- הלקוח יכול לקרוא רק:
  - מה שמותר לו לפי חברות/פרטיות
- כלי מנהל (Admin) משתמש ב‑Admin SDK עם בדיקות מפורשות.

## 4) הקשחת Functions
- אימות טוקן Firebase בכל בקשה.
- ולידציה וסניטיזציה של קלט.
- Rate limits:
  - OTP
  - שליחת הודעות (צ'אט + DM)
  - דיווחים (נגד ספאם)
- Idempotency לפי clientMessageId (בעתיד).
- שגיאות מובנות: BAD_REQUEST / UNAUTHENTICATED / PERMISSION_DENIED / INTERNAL.

## 5) אביוז ובטיחות
- דיווחים לכל סוגי התוכן (יוזר/פוסט/תגובה/DM/צ'אט).
- חסימה הדדית נאכפת:
  - בקריאה (ויזביליות)
  - בשליחה (מניעת אינטראקציה)
- למנהל יש ויזביליות מלאה כולל מחברי אנונימי.

## 6) הגנת מידע (עם חיסכון)
- לצמצם PII:
  - מספר טלפון לשמור כ‑hash אם אפשר (החלטת מדיניות)
- מדיה ב‑Cloud Storage עם הרשאות קשוחות ו‑signed URLs.
